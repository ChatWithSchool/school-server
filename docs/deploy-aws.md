# פריסה אוטומטית: cws-dev ו-cws-stage על ה-EC2

אחרי מיזוג ל-`dev` או ל-`stage` ב-GitHub, הקוד נבדק ואז נפרס לבד לאתר המתאים. המדריך הזה הוא ההקמה החד-פעמית. הוא נבדק בסביבת בדיקה בלבד (nginx, סקריפט הפריסה והחזרה לגרסה קודמת), ולא על המופע שלכם, ולכן ההרצה הראשונה היא גם הבדיקה האמיתית.

## איך זה עובד

| ענף     | כתובת                           | הקליינט                                 | השרת                                         |
| ------- | ------------------------------- | --------------------------------------- | -------------------------------------------- |
| `dev`   | https://cws-dev.safeai613.com   | קבצים ב-`/srv/cws/dev/client/current`   | קונטיינר `cws-dev-server`, פורט מקומי 4101   |
| `stage` | https://cws-stage.safeai613.com | קבצים ב-`/srv/cws/stage/client/current` | קונטיינר `cws-stage-server`, פורט מקומי 4102 |

- ה-nginx שכבר רץ על המופע מגיש את קבצי הקליינט, ומעביר כל בקשה ל-`/api/` אל קונטיינר השרת. הקליינט והשרת באותה כתובת, ולכן אין בעיות CORS והקליינט עובד בלי שינוי.
- **שרת:** CI בונה תמונת Docker, שולח אותה למופע ב-SSH ומפעיל אותה. אם הבדיקה `/api/health` לא עוברת תוך דקה, הסקריפט חוזר לבד לגרסה הקודמת והפריסה מסומנת ככישלון.
- **קליינט:** CI בונה פעם אחת, מעתיק לתיקיית גרסה חדשה ומחליף את הקישור `current` בצעד אחד, בלי רגע שבו האתר שבור.
- הסביבות נפרדות לגמרי: מסד נתונים וסוד JWT משלהן.
- בסיס הנתונים הוא Atlas. הסודות (כתובת המסד וסוד ה-JWT) נשמרים ב-GitHub Environments בלבד, ולא בקוד. בכל פריסה ה-workflow כותב מהם את `server.env` על המופע, כך שאין צורך להיכנס למופע בשביל סודות.

## שלב 1: מפתח SSH ייעודי לפריסה

על המחשב שלך (לא על המופע):

```bash
ssh-keygen -t ed25519 -f cws-deploy -C "github-actions-cws" -N ""
```

נוצרים שני קבצים: `cws-deploy` (המפתח הפרטי, הולך ל-GitHub בלבד) ו-`cws-deploy.pub` (המפתח הציבורי, הולך למופע).

## שלב 2: Atlas

1. צרי שני מסדי נתונים: `cws_dev` ו-`cws_stage`.
2. צרי לכל אחד משתמש משלו, עם הרשאת `readWrite` על המסד שלו בלבד.
3. ב-Network Access הוסיפי את כתובת ה-IP הקבועה של ה-EC2. אם אין למופע Elastic IP, צרי אחד ב-AWS: בלי זה הכתובת משתנה אחרי כיבוי והדלקה, וגם ה-DNS וגם Atlas יפסיקו לעבוד.
4. שמרי את שתי כתובות החיבור לשלב 6.

## שלב 3: DNS ב-Cloudflare

הוסיפי שתי רשומות מסוג A שמצביעות על ה-Elastic IP של המופע:

| שם          | יעד                 |
| ----------- | ------------------- |
| `cws-dev`   | כתובת ה-IP של המופע |
| `cws-stage` | כתובת ה-IP של המופע |

**מצב Proxy:** ליד כל רשומה ב-Cloudflare יש ענן כתום (Proxied) או אפור (DNS only). בשלב הראשון הגדירי **DNS only (אפור)**, כך שהנפקת התעודה בשלב 5 תעבור בלי הפתעות. אחרי שהאתר עובד אפשר להפעיל Proxy, בתנאי שבהגדרות SSL/TLS של Cloudflare המצב הוא **Full (strict)**, אחרת תקבלי לולאת הפניות.

## שלב 4: הכנת המופע (פעם אחת)

על המופע, בהתחברות רגילה:

```bash
git clone git@github.com:<הארגון>/school-server.git
cd school-server/deploy
# העתיקי לכאן את cws-deploy.pub מהמחשב שלך, ואז:
sudo ./setup-ec2.sh ~/cws-deploy.pub
```

הסקריפט יוצר משתמש `deploy`, את התיקיות תחת `/srv/cws`, ומוסיף את הגדרות nginx. הוא בודק קודם שהפורטים 4101 ו-4102 פנויים, ובודק את ההגדרה עם `nginx -t`. אם הבדיקה נכשלת הוא מבטל את ההוספה ולא טוען מחדש את nginx, כך ששני האתרים הקיימים לא נפגעים.

אין צורך לערוך קבצים על המופע: ההגדרות של השרת נכתבות אוטומטית בכל פריסה (שלב 6).

## שלב 5: תעודת HTTPS

```bash
sudo certbot --nginx -d cws-dev.safeai613.com -d cws-stage.safeai613.com
```

Certbot מוסיף את HTTPS ואת ההפניה מ-HTTP. החידוש האוטומטי שכבר מוגדר אצלכם לשני האתרים הקיימים מטפל גם בתעודה הזו.

## שלב 6: GitHub

בכל אחד משני הריפוז (`school-server` ו-`school-client`): Settings, Environments, וצרי שתי סביבות בשמות **`dev`** ו-**`stage`** (השם חייב להיות זהה לשם הענף). בכל סביבה הוסיפי שישה Secrets:

| Secret            | ערך                                                                                                                                    |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `EC2_HOST`        | כתובת ה-IP של המופע                                                                                                                    |
| `EC2_USER`        | `deploy`                                                                                                                               |
| `EC2_SSH_KEY`     | התוכן המלא של הקובץ `cws-deploy` (המפתח הפרטי)                                                                                         |
| `EC2_KNOWN_HOSTS` | הפלט של `ssh-keyscan -t ed25519 <כתובת ה-IP>`, מורץ מהמחשב שלך                                                                         |
| `MONGODB_URI`     | כתובת החיבור של Atlas לסביבה הזו (מסד `cws_dev` או `cws_stage`). אם בסיסמה יש תווים מיוחדים, צריך לקודד אותם בכתובת (למשל `$` כ-`%24`) |
| `JWT_SECRET`      | מחרוזת אקראית, שונה בכל סביבה: `openssl rand -hex 32`                                                                                  |

מומלץ לסביבה `stage`: הפעילי Required reviewers, כך שפריסה ל-stage מחכה לאישור של ראש הצוות.

## שלב 7: הפריסה הראשונה

1. מזגי ל-`dev` בשני הריפוז. בלשונית Actions תראי את `verify` ואחריו `deploy`.
2. פתחי https://cws-dev.safeai613.com. הבדיקה האחרונה ב-workflow כבר מוודאת שהאתר וה-API עונים.
3. אותו דבר ל-`stage`.

**סדר חשוב:** שלבים 1 עד 6 (כולל ששת ה-Secrets) חייבים להסתיים לפני המיזוג הראשון, אחרת שלב `deploy` ייכשל (וזו לא תקלה בקוד).

## נתוני דמה (seed): חשוב

משתמשי הדמה חולקים סיסמה אחת שכתובה בקוד. על מסד מקומי זה בסדר. מסד ב-Atlas נמצא מאחורי אתר שכל אחד יכול לפתוח, ולכן `npm run seed` מסרב לרוץ מולו בלי סיסמה משלך:

```bash
MONGODB_URI="<הכתובת של cws_dev>" SEED_PASSWORD="<לפחות 12 תווים אקראיים>" npm run seed
```

הרצה מהמחשב שלך, לא מהמופע. אל תשתמשי באותה סיסמה בשתי הסביבות.

## חזרה לגרסה קודמת

**שרת:** נעשית לבד אם גרסה חדשה לא עוברת בדיקת תקינות. ידנית: התחברי כ-`deploy`, ואז `cat /srv/cws/dev/.previous-image`, ואז `bash /srv/cws/dev/deploy-server.sh dev <התמונה שהתקבלה>`.

**קליינט:** התחברי כ-`deploy`, ואז:

```bash
cd /srv/cws/dev/client
ls -t releases            # הגרסאות, החדשה ראשונה
ln -sfn releases/<גרסה> current.new && mv -Tf current.new current
```

נשמרות חמש הגרסאות האחרונות.

## בדיקות ולוגים

```bash
docker ps --filter name=cws-
docker logs -f cws-dev-server
curl -s http://127.0.0.1:4101/api/health     # בדיקה מתוך המופע
sudo nginx -t                                # בדיקת הגדרות nginx
```

## מה כדאי לדעת (אבטחה)

- **משתמש `deploy` בקבוצת docker:** מי ששולט בו שולט בכל המכונה. לכן נכנסים אליו רק עם מפתח ה-SSH של הפריסה, ללא סיסמה. אם הצוות יגדל, כדאי לעבור ל-AWS Systems Manager או ל-runner פנימי, כדי לא להשאיר SSH פתוח.
- **סביבות פתוחות:** dev ו-stage נגישים לכל מי שמכיר את הכתובת. הכותרת `noindex` רק מבקשת ממנועי חיפוש לא להציג אותם. הגנה אמיתית אפשר להוסיף בהמשך עם Cloudflare Access.
- **הקונטיינר** רץ בלי הרשאות root, עם מערכת קבצים לקריאה בלבד, ומאזין רק ל-127.0.0.1, כך שאי אפשר לגשת אליו ישירות מהאינטרנט.
- **פורט 22:** כניסה עם מפתח בלבד. בדקי ב-`/etc/ssh/sshd_config` ש-`PasswordAuthentication no`.
- **סודות:** סוד JWT וכתובת המסד שונים בכל סביבה, ונשמרים רק ב-GitHub. כדי להחליף סוד: מעדכנים אותו ב-Environment ומריצים מחדש את ה-workflow (Re-run jobs). החלפת `JWT_SECRET` מנתקת את כל המשתמשים המחוברים.

## תקלות נפוצות

| מה רואים                            | סיבה ופתרון                                                                                                                                                        |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| שלב `Prepare SSH` או `Send` נכשל    | בדקי את ארבעת ה-Secrets של הסביבה. `EC2_KNOWN_HOSTS` חייב להיווצר מאותה כתובת שב-`EC2_HOST`                                                                        |
| `container is 'unhealthy'`          | כנראה `MONGODB_URI` שגוי, או שה-IP לא ב-Network Access של Atlas. ראי `docker logs cws-dev-server`                                                                  |
| `Check the site from outside` נכשל  | DNS או תעודה עדיין לא מוכנים (שלבים 3 ו-5), או שמצב SSL ב-Cloudflare אינו Full (strict)                                                                            |
| `ERR_TOO_MANY_REDIRECTS`            | Proxy דלוק ומצב SSL ב-Cloudflare הוא Flexible: להחליף ל-Full (strict)                                                                                              |
| `unknown shorthand flag: 'p' in -p` | חסר התוסף Docker Compose במופע. ב-Ubuntu: `sudo apt-get install -y docker-compose-v2` (אם Docker הותקן מהמאגר של Docker: `docker-compose-plugin`), ואז Re-run jobs |
| `setup-ec2.sh` מדווח שפורט תפוס     | משהו אחר משתמש ב-4101 או ב-4102: לשנות את הפורט ב-`deploy-server.sh` וב-`nginx/cws.conf`                                                                           |
